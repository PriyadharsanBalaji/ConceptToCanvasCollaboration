# LLM Comparison Pipeline (Manual Workflow)

Welcome to the **LLM Comparison Pipeline**. This directory acts as an evaluation sandbox to compare the Manim Community Edition (ManimCE) animations generated by a local `manim-coder` model against state-of-the-art API models like **Claude** and **Gemini**.

## 🔄 Pipeline Stages: Input & Output

This pipeline sits on top of the original Educational Pipeline's outputs. Here is exactly what happens at every stage of the comparison workflow:

### Stage 1: Prompt Extraction (`extract_manim_prompts.py`)
- **Input:** A completed `storyboard.json` file from the main pipeline.
- **Process:** Parses the JSON to extract narration, visual intent, and text for every scene. Injects these into the strict Manim Prompt Template.
- **Output:** Individual `.txt` files (e.g., `scene_001_prompt.txt`) containing the exact prompt strings, saved into `RunX/inputs/claude/` and `gemini/`. It also creates empty placeholder `.py` files in the output directories.

### Stage 2: Code Generation (Manual via UI)
- **Input:** The generated `.txt` prompt files.
- **Process:** The user pastes the System Prompt and User Prompt into Claude or Gemini's web interface.
- **Output:** Python code generated by the LLM, which the user pastes into the pre-created `scene_XXX.py` placeholder files in `RunX/outputs/claude/` or `gemini/`.

### Stage 3: Rendering & Evaluation (`evaluators/render_and_compare.py`)
- **Input:** The directory containing the LLM-generated `.py` files (e.g., `RunX/outputs/claude/book_name`).
- **Process:** Automates the Manim CE compilation process. It uses a specific local virtual environment where Manim is installed. To prevent different models from overwriting each other, it uses the `--media_dir` flag to isolate output videos.
- **Output:** A console report detailing the compile success rate, and the rendered `.mp4` files stored directly inside a local `media/videos` folder (e.g., `RunX/outputs/claude/book_name/media/videos`).

### Stage 4: Audio Mixing & Stitching (`evaluators/stitch_videos.py`)
- **Input:** The local `media/videos` directory containing the rendered `.mp4` scenes, and the original `audio` directory containing TTS `.mp3` files from the main pipeline.
- **Process:** Leverages FFmpeg to iterate through the rendered videos, find their matching `.mp3` narration, mix them together frame-perfectly, and then concatenate all mixed scenes chronologically.
- **Output:** A single, continuous, fully-narrated video file named `full_stitched_video.mp4`.

## 🏗️ Directory Architecture

To keep tests highly organized without overwriting data, everything is structured by "Runs" (e.g., `Run1`, `Run2`).

```text
ComparisionPipeline/
├── evaluators/
│   ├── render_and_compare.py      # Evaluates Manim syntax and renders video
│   └── stitch_videos.py           # Mixes audio and concatenates final video
├── extract_manim_prompts.py       # Main extraction script
└── Run1/
    ├── InputRunJson/              # Drop downloaded storyboard.json & audio folders here
    ├── inputs/
    │   ├── claude/                # Contains generated .txt prompts to send to Claude
    │   └── gemini/                # Contains generated .txt prompts to send to Gemini
    └── outputs/
        ├── claude/                # Drop Claude's python code files here
        └── gemini/                # Drop Gemini's python code files here
```

## 🚀 How to Run the Pipeline

### Step 1: Extract the Prompts
Place your downloaded `storyboard.json` (and `audio` folder) into `Run1/InputRunJson/your_book_name/`. Then run:
```bash
cd E:\ProjectM\ParthPipeline\ComparisionPipeline
python extract_manim_prompts.py "Run1\InputRunJson\your_book_name\storyboard.json" Run1
```
*This instantly generates your prompts in `inputs/` and empty `.py` placeholders in `outputs/`.*

### Step 2: Generate Code via LLM
Open `Run1/inputs/claude/your_book_name/scene_001_prompt.txt`. Paste the System Instructions and User Prompt into Claude/Gemini. 
Copy their Python response, and paste it into the matching empty file at `Run1/outputs/claude/your_book_name/scene_001.py`.

### Step 3: Render the Scenes
Navigate **into** the output directory to isolate the renders, then run the evaluator:
```bash
cd E:\ProjectM\ParthPipeline\ComparisionPipeline\Run1\outputs\claude\your_book_name
python E:\ProjectM\ParthPipeline\ComparisionPipeline\evaluators\render_and_compare.py .
```
*Failed compiles indicate LLM hallucinations. Successful compiles generate `.mp4` files in the local `media/videos` folder.*

### Step 4: Mix Audio and Stitch
While still in the same directory, run the stitching script, passing it your media folder and your original audio folder:
```bash
python E:\ProjectM\ParthPipeline\ComparisionPipeline\evaluators\stitch_videos.py media/videos "E:\ProjectM\ParthPipeline\ComparisionPipeline\Run1\InputRunJson\your_book_name\audio"
```
*Your final video will be saved as `full_stitched_video.mp4`!*

## 🧠 Prompt Architecture

To ensure a fair comparison, the prompts fed to Claude/Gemini are identical to the ones fed to the local `manim-coder`. 

### The System Prompt
The LLMs are given 13 strict rules to prevent standard AI hallucinations in Manim. Key rules include:
- Must import standard `from manim import *`
- One class per scene, inheriting strictly from `Scene`.
- Naming convention enforcement (`Scene_XXX`).
- Forced 3D coordinates (e.g., `[x, y, 0]`) to prevent 2D array crashes.
- Banning external images (`ImageMobject`) to enforce pure vector math.

### The User Prompt
The prompt dynamically injects the JSON storyboard data using this structure:
```text
SCENE ID: {scene_id}
TITLE: {title}
DURATION: ~{duration}s of animation

NARRATION (what the voiceover says — animate in sync with this):
{narration}

VISUAL DESCRIPTION (what the viewer should see):
{visual_description}

MANIM INTENT (specific animation instructions):
{manim_intent}

KEY OBJECTS TO USE: {key_objects}

ON-SCREEN TEXT/EQUATIONS:
{on_screen_text}

BACKGROUND COLOR: {bg_color}
ACCENT COLORS: {accent_colors}
```
